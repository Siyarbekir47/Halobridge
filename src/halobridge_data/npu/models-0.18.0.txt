# Our NPU models (the bare names HALOGEN_NPU_MODELS takes in the default mode),
# and the files each must hold. Read by the entrypoint before anything starts:
# every file's size and sha256 must match. Filled by the release that publishes
# the files; one line a model, then one line a file:
#
#   model <id> repo=<org>/<repo> revision=<commit> task=decision|embedding|score|classify|generate|image|transcribe [devices=<id>] source=<org>/<repo>@<commit> license=<spdx>
#
# The task is what the front end serves the model for: decision (the deciders'
# decisions), embedding (/v1/embeddings), score (rerank), classify (moderation,
# /v1/moderations) and generate (text generation, /v1/chat/completions; the
# generation model's devices/ also holds its decode program, and its one cache
# capacity bounds the prompt plus max_tokens) and image (text to image,
# /v1/images/generations: FLUX.2-klein-4B; its devices/ holds a program a
# resolution, its text encoder's and the taef2 decoder's weights) and transcribe (speech to text,
# /v1/audio/transcriptions: Qwen3-ASR; its tokenizer.json is built from the checkpoint's vocabulary and merges).
#   file  <id> <path under /models/npu/<id>/> <bytes> <sha256>
#
# The paths are devices/devices.hnpm, devices/<shape>.elf, devices/consts.hnpb,
# devices/NOTICE.md, <id>.hnpw and tokenizer/tokenizer.json. A model whose line
# names devices=<other id> holds no devices/ of its own: it runs on that model's
# (fetched alone under HALOGEN_DOWNLOAD), and lists only its weight file and
# tokenizer (the dense models share one set: the device never reads the
# vocabulary). A user's own fine-tune of one of these runs on the same devices/
# files (its weight file is converted from the user's checkpoint by the NPU
# engine).
#
# An empty repo= (and revision=) is a model whose files are recorded but have no
# download source yet: the files are still checked, and HALOGEN_DOWNLOAD names
# the missing files instead of fetching them. A release fills repo= and
# revision= when it uploads the files.
